OKF note: this port follows upstream's code, not the [OKF spec](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) or blog posts. Upstream 0.4.1 (#728) made every optional-metadata failure recoverable: invalid recognized fields are repaired or removed deterministically instead of aborting a run, and a trust assertion that cannot be proven conformant is removed rather than rewritten. Upstream 0.4.0 (#581) adopted OKF v0.2: the bundle-root index carries `okf_version: "0.2"`, `generated: {by, at}` supersedes `timestamp` as code-owned provenance (SPEC §5.1), `verified` carries trust events (§5.2), `sources` carries provenance resources, and `status`/`stale_after` are validated when present. `timestamp` stays tolerated for v0.1 pages (§13.1) but is dropped from any page whose body changes. Still not implemented: nothing writes a `log.md` update history (spec §7) — reserved-file handling tolerates one, but keep this port from generating it until upstream does. This port additionally omits `verified` and the `.claims` sidecars; see `skills/openwiki/SKILL.md` Step 5 for why.

## Sync procedure

1. Refresh a local upstream clone (this machine: `~/Projects/oss/openwiki`; if it is shallow, run `git fetch --unshallow` first). That clone may sit on a fork branch — fetch and diff against the release tag or `origin/main` rather than assuming `git pull` lands on upstream `main`.
2. List relevant changes: `git log <pinned>..<new tag> --oneline -- src/agent/prompt.ts src/agent/prompts/ src/agent/repository-prompts.ts src/agent/repository-runner.ts src/agent/wiki-finalizer.ts src/agent/wiki-replacement.ts src/agent/wiki-link-validator.ts src/agent/openwiki-ignore.ts src/agent/utils.ts src/agent/types.ts src/agent/docs-only-backend.ts src/agent/okf-middleware.ts src/agent/translation-middleware.ts src/claims/ src/generation/ src/platform/language.ts src/okf/ src/mermaid/ src/ingestion/code-mode.ts src/ingestion/ingestion.ts src/config/constants.ts integrations/ skills/ examples/`
3. No output → report that the skills are current with upstream, and stop. Output → review each commit's diff and port it per the mapping above. Also `git ls-tree -r --name-only <new tag> -- src` and compare with the mapping: 0.4.0 arrived as whole new directories (`src/claims/`, `src/generation/`, `src/integrations/`) that a path-scoped `git log` over the old mapping would have missed entirely.
4. The prompt files (`skills/openwiki/references/prompt-planner.md` / `prompt-page.md` and the personal skill's Step 3) are verbatim, line-mapped copies of upstream's templates — prompt changes apply as near-direct diffs; keep `[adapted]`/`[omitted]` markers intact. When a prompt file is heavy with `${...}` interpolation, diff it against the pin with the display-path constants substituted, so a mechanical constant extraction does not read as a text change.
5. The two wiki skills carry deliberately identical copies of `references/index-labels.md` (skills install per-directory, so they cannot share one file). After any sync that touches `src/okf/index-labels.ts`, update both and verify: `diff skills/openwiki/references/index-labels.md skills/openwiki-personal/references/index-labels.md` must be empty.
6. Update the pinned commit above and add a CHANGELOG entry describing what was ported.
