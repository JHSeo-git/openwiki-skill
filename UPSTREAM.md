## File mapping

Only these upstream paths carry skill-relevant behavior. Changes anywhere else (CLI/UI, provider plumbing, credentials/OAuth onboarding, connector runtimes, schedulers, tests) are intentionally out of scope.

Upstream 0.4.0 (#713) replaced repository generation with a resumable page-job lifecycle, so the repository skill's prompt sources moved out of `src/agent/prompts/code.ts` (which now holds only the `chat` template) into `src/agent/repository-prompts.ts` + `src/claims/guidance.ts`, and its deterministic passes moved behind `src/agent/wiki-finalizer.ts`. Local-wiki (personal) mode still runs on the shared agent and the shared prompt engine.

Upstream 0.5.0 added two things that reshape the mapping. (1) #720 made resumability durable *per page* and portable across hosts via a committed `openwiki/.page-manifest.json` ledger (`src/generation/page-manifest.ts`), which also rewrote the planner's update context into per-page baseline windows, relaxed resume's producer-actor lock, and made partial progress a publishable CI result. (2) #769 made Claim reconciliation **sparse** — the page worker submits only the decisions its edits require, omission now *retains* rather than retracts, and the complete set moved behind an on-demand `inspect_claims` tool. Both land in a port with no `.claims` sidecar, so read the "port fidelity" notes below before assuming a mechanical copy is correct.

Two 0.5.0 decisions to re-examine rather than re-derive next time. **The manifest write stays out** as long as `buildManifestEntry` requires a `verification`-bearing `.claims` sidecar; if upstream ever admits a sidecar-free entry, revisit, because writing one would let this port hand native and CI runs real per-page baselines instead of only consuming theirs. **Sparse Claims reconciliation stays mostly inert** for the same root cause — no sidecar means no persisted Claim ids — so if the sidecar decision ever changes, `prompt-page.md`'s opening note and its gates 4–5 are where the id-keyed halves come back to life. Both hinge on one omission; do not treat them as two independent questions.

Two 0.4.0 regressions are deliberately *not* reproduced as removals: repository generation prompts no longer render the shared "Link integrity" section, and `createDiagramInstructions` lost its last production call site (only the personal prompts still inline both blocks) — yet the deterministic Mermaid and link passes still run and still stamp repair comments on every repository run, so `prompt-page.md` keeps a trimmed version of both under an explicit `[omitted]` note. If upstream re-attaches them to the page prompt, replace that note with the verbatim text.

OKF note: this port follows upstream's code, not the [OKF spec](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) or blog posts. Upstream 0.4.1 (#728) made every optional-metadata failure recoverable: invalid recognized fields are repaired or removed deterministically instead of aborting a run, and a trust assertion that cannot be proven conformant is removed rather than rewritten. Upstream 0.4.0 (#581) adopted OKF v0.2: the bundle-root index carries `okf_version: "0.2"`, `generated: {by, at}` supersedes `timestamp` as code-owned provenance (SPEC §5.1), `verified` carries trust events (§5.2), `sources` carries provenance resources, and `status`/`stale_after` are validated when present. `timestamp` stays tolerated for v0.1 pages (§13.1) but is dropped from any page whose body changes. Still not implemented: nothing writes a `log.md` update history (spec §7) — reserved-file handling tolerates one, but keep this port from generating it until upstream does. This port additionally omits `verified` and the `.claims` sidecars; see `skills/openwiki/SKILL.md` Step 5 for why.

## Sync procedure

1. Refresh a local upstream clone (this machine: `~/Projects/oss/openwiki`; if it is shallow, run `git fetch --unshallow` first). That clone may sit on a fork branch — fetch and diff against the release tag or `origin/main` rather than assuming `git pull` lands on upstream `main`.
2. List relevant changes: `git log <pinned>..<new tag> --oneline -- src/agent/prompt.ts src/agent/prompts/ src/agent/repository-prompts.ts src/agent/repository-runner.ts src/agent/wiki-finalizer.ts src/agent/wiki-replacement.ts src/agent/wiki-link-validator.ts src/agent/openwiki-ignore.ts src/agent/utils.ts src/agent/types.ts src/agent/docs-only-backend.ts src/agent/okf-middleware.ts src/agent/translation-middleware.ts src/claims/ src/generation/ src/platform/language.ts src/okf/ src/mermaid/ src/ingestion/code-mode.ts src/ingestion/ingestion.ts src/config/constants.ts src/integrations/install/registry.ts integrations/ skills/ examples/`
3. No output → report that the skills are current with upstream, and stop. Output → review each commit's diff and port it per the mapping above. Also `git ls-tree -r --name-only <new tag> -- src` and compare with the mapping: 0.4.0 arrived as whole new directories (`src/claims/`, `src/generation/`, `src/integrations/`) that a path-scoped `git log` over the old mapping would have missed entirely. Scan the *full* log too, not only the scoped one — 0.5.2's #870 added a `producerActor` in `src/integrations/install/registry.ts`, which the scoped command did not cover until this sync added it, and a host missing from the actor list is exactly the kind of omission the scoped log is supposed to prevent.
4. The prompt files (`skills/openwiki/references/prompt-planner.md` / `prompt-page.md` and the personal skill's Step 3) are verbatim, line-mapped copies of upstream's templates — prompt changes apply as near-direct diffs; keep `[adapted]`/`[omitted]` markers intact. When a prompt file is heavy with `${...}` interpolation, diff it against the pin with the display-path constants substituted, so a mechanical constant extraction does not read as a text change.
5. The two wiki skills carry deliberately identical copies of `references/index-labels.md` (skills install per-directory, so they cannot share one file). After any sync that touches `src/okf/index-labels.ts`, update both and verify: `diff skills/openwiki/references/index-labels.md skills/openwiki-personal/references/index-labels.md` must be empty.
6. Update the pinned commit above and add a CHANGELOG entry describing what was ported.
